# Getting Started

## Overview

The Nexus API allows users to interact with the Nexus platform programmatically. Authentication
is handled through the use of tokens which need to be passed in request headers.

## Authentication

Authentication is done via tokens. A token can be generated by navigating to
nexus.example.com/settings/tokens. The token needs to be included in all API requests using the
Authorization header. The format that should be used is: `Authorization: Bearer <token>`.

Tokens will expire after 90 days and will need to be regenerated. There is no token refresh
mechanism that is currently supported.

## Making your first request

Once authentication has been configured, API calls can be made. The base URL that should be
used for the API is `https://api.nexus.example.com/v1`.

The following is an example of how a build can be triggered:

```
POST /builds
Authorization: Bearer <your_token>
Content-Type: application/json

{
  "source_ref": "main"
}
```

A response will be returned with the build information. The status field will show "queued"
which means the build has been added to the queue. The build ID should be noted as it will be
needed for subsequent requests.

To check on the status of the build, a GET request to `/builds/{buildId}` can be made using
the build ID from the previous response. This should be done until the status shows "succeeded"
or "failed".

Once a build is in the "succeeded" state, it can be published by making a POST request to
`/builds/{buildId}/publish`.

## Error handling

In case of errors, the API will return an error response. A code and message will be provided.
The HTTP status code that is returned will also indicate the type of error that was encountered.
Various error codes are possible depending on the operation being performed.
